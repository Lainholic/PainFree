## 질문 1. 클라이언트 파싱 조작 리스크 — P0인가?

### 1-1. 환님 논리의 타당성 평가

**타당한 부분 (인정):** 환자 본인이 원무과에 제출할 목적으로 영수증을 위조할 실익은 실제로 희박합니다. 위조의 이해당사자는 환자가 아니라 **제3자(보험 사기, 대리 청구업자, 부정수급 조직)** 이며, 이들은 클라이언트 조작이 아니라 **원본 위조**를 합니다. 따라서 "환자가 조작할 이유가 없다"는 지적은 **위협 모델(Threat Model) 설정상 정확**합니다.

**보정이 필요한 부분:** 그러나 심사위원 관점에서 이 항목이 P0로 분류되는 이유는 "환자가 조작해서 이득을 본다"가 아니라, **"파싱 결과가 서버의 신뢰 경계(Trust Boundary)를 넘어 그대로 다운스트림(EMR 연동, 보험 청구 API, AI 요약)으로 흘러갈 때 무결성(Integrity) 보증이 없다"** 는 아키텍처 결함입니다. 즉 **보안 사고 가능성**이 아니라 **감사(Audit) 추적 불가능성**이 문제입니다.

### 1-2. 제안: "경량 무결성 파이프라인" (Heavy Session 불필요)

은행식 서버 세션·전자서명 강제 없이, **3개 레이어로 90%의 리스크를 5%의 공수로 제거**하는 구조를 제안합니다.

| 레이어 | 구현 | 비용 | 심사 어필 포인트 |
|---|---|---|---|
| **L1. 원본 보존 (Immutable Raw)** | 클라이언트는 파싱 결과만 보내지 않고 **원본 이미지 해시(SHA-256) + 파싱 JSON을 함께 업로드**. 서버는 해시를 저장하고 파싱 결과에 `raw_hash` 필드를 바인딩 | 매우 낮음 (해시 1줄) | "원본-파싱 결과 무결성 바인딩" — 감사 로그 요건 충족 |
| **L2. 서버 재검증 (Selective Re-parse)** | 서버는 **금액·날짜·병원명 등 핵심 필드만** 경량 OCR/VLM으로 재파싱하여 클라이언트 값과 대조. 불일치 시 `flagged: true` 마킹 후 사용자 확인 UI 트리거 | 중간 (핵심 필드만) | "서버 사이드 검증 계층 존재" — 심사위원이 가장 좋아하는 문구 |
| **L3. 신뢰 등급 표기 (Provenance Tag)** | 다운스트림(EMR/청구)으로 전달되는 모든 레코드에 `trust_level: client_parsed / server_verified` 태그 부착 | 낮음 | "다운스트림이 신뢰 등급을 인지" — 규제 아키텍처 모범 사례 |

**핵심 메시지:** "환자를 의심하는 보안"이 아니라 **"다운스트림 시스템을 보호하는 데이터 계보(Data Provenance)"** 로 프레이밍을 전환하십시오. 이 프레이밍이면 환님의 실용성 논리와 심사위원의 아키텍처 요구를 **동시에 만족**합니다. P0 → P2로 강등 가능하며, 발표 자료에는 "P0 아님, L1+L3로 완화"라고 명시하는 것이 오히려 **성숙한 판단력의 증거**로 채점됩니다.

## 질문 2. 명시적 동의(Consent) — 팝업 하나로 끝나는가?

### 2-1. 결론: "체크박스 하나"로는 부족하며, **3중 구조**가 필요합니다

환님 지적대로 동의는 필수이자 핵심입니다. 그러나 글로벌 규제 3종(HIPAA / GDPR / 한국 개보법)은 **동의의 "형식"이 아니라 "입증 가능성(Accountability)"** 을 요구합니다. 심사위원은 "동의 받았습니다"가 아니라 **"동의를 어떻게 증명하십니까"** 를 봅니다.

### 2-2. 규제별 요구사항 매핑

| 규제 | 핵심 요구 | UI/UX 반영 | 백엔드 반영 |
|---|---|---|---|
| **GDPR Art.7** | 동의의 자유로운 철회, 목적별 분리 동의, 증명 책임 | 목적별 개별 체크박스(수집/외부AI전송/보관), 철회 버튼 상시 노출 | 동의 이력 테이블(버전·타임스탬프·IP·동의문 버전) |
| **HIPAA Authorization** | 특정 목적·수신자·만료일 명시, 재위탁 시 재동의 | "Nebius(NVIDIA) 클라우드로 전송됨" **수신자 명시** | BAA(위탁계약) 문서 링크, 전송 로그 |
| **한국 개보법 §17, §28-8** | 국외 이전 별도 고지·동의, 민감정보(건강) 별도 동의 | "국외 이전" 별도 체크박스 + 이전 국가/수신자/목적/보유기간 표 | 국외이전 동의 이력 별도 저장 |

### 2-3. 실전 UI/UX 배치 (심사 감점 방지 3원칙)

1. **계층형 동의 (Layered Consent):** ① 필수(서비스 제공) / ② 선택(외부 AI 전송) / ③ 선택(연구·개선) — **②를 필수에 번들하면 GDPR 위반**으로 즉시 감점. 반드시 분리.
2. **Just-in-Time 동의:** 앱 진입 시 일괄 동의가 아니라, **첫 영수증 업로드 직전**에 외부 AI 전송 동의 팝업. "왜 지금 필요한가"를 문맥과 함께 제시.
3. **철회 가능성의 가시화:** 설정 화면에 "AI 전송 동의 철회" 버튼 상시 노출. 철회 시 **즉시 파이프라인이 로컬/비-AI 경로로 폴백**되는 것을 데모에서 시연하면 강력한 가점 요소.

### 2-4. 백엔드 처리 (감사 대응 최소 구현)

```
consent_log {
  user_id, consent_type(수집/외부전송/국외이전),
  policy_version, granted_at, revoked_at,
  ip_hash, user_agent_hash,  // 증명용
  ai_provider("nebius/nvidia-nemotron"), data_scope
}
```
- **동의문 버전 관리**: 정책 변경 시 재동의 트리거.
- **전송 전 게이트**: 외부 AI 호출 직전 `consent_check()` 미들웨어 — 동의 없으면 503 + 로컬 폴백.
- **데모 시나리오**: "동의 철회 → AI 요약 기능 비활성화 → 원본 파싱만 동작"을 라이브로 보여주십시오. 심사위원이 가장 높게 평가하는 **"규제를 기능으로 구현했다"** 의 증거입니다.

**핵심 메시지:** 동의는 "법무 체크박스"가 아니라 **"런타임 게이트 + 감사 로그 + 폴백 경로"** 로 구현될 때 감점이 사라집니다.

## 질문 3. 모델 전략 — Nemotron 3 Ultra 550B는 득인가 실인가?

### 3-1. 냉정한 득실 분석 (심사 기준 4축)

| 심사 축 | 550B 유지 시 | 평가 |
|---|---|---|
| **NVIDIA 생태계 기여도** | 최고 사양 사용은 "진정성" 어필. 단, **심사위원은 크기보다 "적재적소"를 봄** | △ (과시는 되나 최적화 역량 의심) |
| **레이턴시** | 영수증 1건 파싱에 수 초~수십 초. **데모 라이브 시연 리스크** | ✗ (치명적) |
| **비용** | 해커톤 크레딧 소진 속도, 반복 실험 불가 | ✗ |
| **실용성/생산성** | 파싱·분류 태스크에 550B는 **오버킬**. "왜 이 모델?" 질문에 답 못하면 감점 | ✗ |

**결론: 550B 단독 유지는 실(失)이 압도적입니다.** 단, **"550B를 아예 언급하지 않는 것"도 손실**입니다. NVIDIA 트랙에서 대형 모델 활용 서사는 가점 요소이므로, **"어디에 쓸 것인가"를 정당화하는 방식**으로 전환해야 합니다.

### 3-2. 제안: 3-Tier 하이브리드 아키텍처 (우승 확률 최대화)

```
[입력: 영수증 이미지]
        │
        ▼
┌─────────────────────────────┐
│ Tier 1: 8B (Llama 3.1 8B /   │  ← OCR 후 구조화 파싱, 필드 분류
│ Nemotron 8B 계열)            │     레이턴시 <1s, 비용 최소
└─────────────────────────────┘
        │ (구조화 JSON)
        ▼
┌─────────────────────────────┐
│ Tier 2: 70B (Nemotron 70B /  │  ← 복합 추론: 항목-진료 매칭,
│ Llama 3.1 70B)               │     이상치 탐지, 요약 생성
└─────────────────────────────┘
        │ (에스컬레이션 조건 충족 시에만)
        ▼
┌─────────────────────────────┐
│ Tier 3: Nemotron 3 Ultra 550B│  ← 모호 케이스/분쟁 조정/복잡 다문서
│ (조건부 호출)                 │     추론. 전체 트래픽의 <5%
└─────────────────────────────┘
```

**라우팅 규칙 (핵심):**
- Tier 1 신뢰도 ≥ 0.9 → Tier 2 생략, 바로 응답 (레이턴시 최소화)
- Tier 2 신뢰도 < 0.7 또는 다문서 교차검증 필요 → **Tier 3(550B) 에스컬레이션**
- 이 구조는 **"550B를 썼다"는 서사와 "레이턴시/비용을 최적화했다"는 서사를 동시에 확보**
