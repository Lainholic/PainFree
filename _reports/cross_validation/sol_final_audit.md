# 2. 개인정보 보호·동의: 배포 차단 사항

## P-01 — 원본 영수증이 마스킹 전에 외부 OCR로 전송됨
**심각도: 높음**

**근거**

- `receipt_pipeline.py / ocr_image()`:
  ```python
  optimized_url = _prepare_image(data_url)
  ```
  이어서 기본 OCR 요청과 fallback 요청 모두:
  ```python
  {"type": "image_url", "image_url": {"url": optimized_url}}
  ```
- `_mask_identifiers()`는 `build_reasoning_messages()`에서만 호출됩니다.

**문제**

이름·환자번호·주소·진료내역이 포함된 이미지가 먼저 외부 API로 전달됩니다. 이후 추론 단계의 텍스트 마스킹은 **OCR 단계의 개인정보 전송을 방지하지 않습니다.**

`_prepare_image()`의 JPEG 변환을 개인정보 비식별화로 볼 수도 없습니다. 이미지에 찍힌 개인정보는 남습니다.

**텍스트 변경안**

- 동의 안내에서 “원본 영수증 이미지가 외부 OCR 모델에 전송된다”는 사실을 명시.
- 개인정보 제거를 주장하려면 외부 전송 **이전** 로컬 가림 처리와 사용자 미리보기 확인을 구현.
- 보관기간, 처리지역, 위탁·국외이전 여부와 적용 법적 요건은 공급자 계약 및 실제 처리 흐름에 근거해 별도 확인.

**텍스트 변경안**

외부 전송 직전에 **전체 요청 객체**를 대상으로 최소화·마스킹을 수행해야 합니다. 원본 표시용 데이터와 외부 전송용 데이터를 분리하고, 식별자가 들어간 청구행은 원문 복사보다 개인정보 보호가 우선하도록 규칙을 명시하십시오.

**심각도: 중간~높음**

| 입력 | 예상 문제 |
|---|---|

| `receipt.lines`가 문자열 | 문자별 순회 후 잘못된 재파싱 |

**텍스트 변경안**

최상위 객체, 필드 타입, 배열 길이, 문자열 길이, 정수 범위를 명시하고 오류는 400/422로 반환하십시오. 허용 범위를 벗어난 VAS를 조용히 보정하기보다 거절해야 기록 왜곡을 막을 수 있습니다.

# 4. 파서와 추론 품질: 잘못된 감사 근거 생성

## R-01 — 한국 표의 0원과 열 의미를 잘못 처리
**심각도: 높음**

`parse_receipt()`의 한국 세로행 처리:
```python
if raw_val.isdigit() and len(raw_val) <= 8 and not lines[j].startswith("0"):
```

```python
is_noncovered = len(nums) >= 3 and val_floats[-1] > 0
main_amt = val_floats[-1] if is_noncovered else val_floats[0]
```

**결함**

- 정상적인 `0`원 셀에서 숫자 수집이 중단됩니다.
- 열 머리글을 보지 않고 “세 번째 이상 숫자의 마지막 값이 양수”라는 이유로 비급여를 확정합니다.
- 급여 본인부담·공단부담·전액본인부담·비급여의 의미가 혼동됩니다.

이는 단순 표시 오류가 아니라 **잘못된 비급여 확인 질문 생성**으로 이어집니다. 열 구조를 복원할 수 없으면 비급여는 `unknown`이어야 합니다.

**심각도: 높음**

```python
total = max(t["value"] for t in totals)
```

```python
if re.search(r"[\u4e00-\u9fff]", blob):
```

- 총진료비·환자부담·수납액 중 가장 큰 숫자를 합계로 선택합니다.

국가별 청구 프레임워크를 고르는 프롬프트와 결합되면 잘못된 법제 안내로 확대됩니다. 통화·국가·합계 역할을 명시적으로 확인하고 불명확하면 유보해야 합니다.

## R-03 — 통증·활동량으로 청구 적정성을 뒷받침하도록 유도
**심각도: 높음**

시스템 프롬프트는 임상적 필요성·급여·중복 등을 묻도록 하고 출력 스키마는:
```python
"reasoning": "evidence-based explanation linking patient condition and wearable drop to the billed lines"
```
을 요구합니다.

걸음 감소·VAS·기저질환만으로 코드 수준, 급여 적격성, 치료 필요성이나 중복 청구를 판정할 수 없습니다. 직접 관련이 없는 경우에도 연결 근거를 만들어야 하는 압력이 있습니다.

**텍스트 변경안**

“통증·활동량은 환자 설명의 맥락일 뿐 청구 오류나 의료 필요성의 증거가 아니다”를 명시하고, 연관 근거가 없으면 연결하지 않도록 하십시오. 국가별 법적 제도 언급에는 검증된 자료와 적용 조건이 필요합니다.

## R-04 — 프롬프트 주입·출력 검증 부재
**심각도: 높음**

OCR 원문·환자 자유 입력을 같은 사용자 메시지에 연결합니다. 악성 지시가 문서에 포함되어도 데이터로만 취급하도록 하는 명시적 경계가 없습니다.

`reason()`은 JSON 파싱 후 곧바로:
```python
result["status"] = "success"
```
를 설정합니다.

검증되지 않는 항목:

- 필수 키·필드 타입·길이
- `target_item`의 실제 원문 존재
- 개인정보 출력
- 금지된 의료·법률 단정
- 출력 토큰 잘림 여부

`_extract_json()`의 닫는 문자 보정은 불완전 응답을 정상 결과처럼 받아들일 수 있습니다. JSON 형식 성공과 사실성 검증은 분리해야 합니다.

# 5. 아키텍처·해커톤 경쟁력

## A-01 — 모델 설정 변경과 성능·제공 사실은 분리해야 함

다음 문자열은 확인됩니다.
```python
REASONING_MODEL = "nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B"
```

그러나 제공 자료만으로 모델의 현재 Nebius 제공 여부, 공식 모델 카드, 실제 활성 파라미터 수, 가격, 추론 성능을 검증할 수 없습니다. 모델명만으로 MoE 성능이나 이 과제에 대한 적절성을 확정할 수 없습니다.

**7~10초 실측은 사용자 제공 주장으로 별도 분류합니다.** 측정 로그·표본 수·입출력 토큰 수·실패율이 없습니다.

## A-02 — 전체 지연은 추론 시간보다 길고 fallback이 직렬임

- 기본 OCR `timeout=90`
- fallback OCR `timeout=120`
- 추론 `timeout=120`

이 값은 실측 지연도, 전체 작업의 엄격한 총 제한시간도 아닙니다. 다만 직렬 실패 경로에서 긴 대기가 가능함을 보여줍니다.

한국 표는 다음 조건 때문에 50줄 미만이면 추가 OCR을 호출합니다.
```python
need_fallback = ... or (is_kr_table and len(lines) < 50)
```

짧지만 정상인 영수증도 재호출할 수 있습니다. fallback 결과는 비어 있지 않으면 교체되며 더 정확한지 비교하지 않습니다.

**필요한 경쟁력 증거**

- OCR·파싱·추론·전체 p50/p95
- fallback 발생률과 정확도 개선량
- 한국 표의 항목·금액·급여 열 정확도
- 개인정보 누출률·환각률·원문 일치율
- 요청당 비용과 실패율

공식 해커톤 심사 기준은 제공되지 않았으므로 수상 경쟁력 판정은 유보합니다.

# 6. UI/UX·접근성

## U-01 — 모델 표시가 실제 설정과 불일치
**심각도: 중간**

HTML의 사용자 노출 배지:
```html
<span>Nemotron 3 Ultra</span>
```

백엔드는 Nano 설정입니다. 주석에도 `550B`가 남아 있습니다. 사용자 배지는 즉시 수정해야 하는 사실성 결함입니다. 실제 응답의 모델명을 표시하되 추론 모델과 OCR 모델을 구분하십시오.

## U-02 — VAS 슬라이더의 접근 가능한 이름 누락
**심각도: 중간**

```html
<input type="range" id="vasSlider" ...>
```

앞의 설명은 `span`이며 연결된 `label`, `aria-label`, `aria-labelledby`가 없습니다. 선택 칩에도 제공 마크업 기준 `aria-pressed`나 선택 상태 의미가 없습니다.

## U-03 — 업로드 진입점의 키보드 접근 위험
**심각도: 중간**

파일 입력은 `class="hidden"`이고 클릭 대상은 `label` 내부 `div`입니다. Tailwind 스타일이 적용되면 입력은 표시·포커스 대상에서 제외됩니다. 보이는 진입점은 키보드 버튼이 아닙니다.

접근 가능한 버튼 또는 시각적으로만 숨긴 파일 입력으로 변경해야 합니다.

## U-04 — 확대 허용만으로 접근성 개선 완료를 선언할 수 없음

확대 허용 태그는 확인됩니다. 그러나 다음은 미검증입니다.

- 확대 시 가로 스크롤·고정 내비게이션의 콘텐츠 가림
- 동의 모달의 초점 이동·가두기·복귀·Escape 처리
- 스캔·추론 상태의 `aria-live`
- 대비·터치 목표 크기
- 영어 전환 시 문서 `lang` 갱신

제공 CSS에는 반복 애니메이션이 있지만 `prefers-reduced-motion` 대응이 보이지 않습니다.
