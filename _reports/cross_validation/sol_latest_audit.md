## 최종 판정

**실제 환자 청구서와 건강정보를 취급하는 배포에는 보류가 필요합니다.**

핵심 문제는 다음 네 가지입니다:
1. 서버 재파싱은 원본 진위나 OCR 출처를 검증하지 않습니다.
2. 청구된 약물을 현재 복용·투약 상태처럼 해석할 수 있으며, 안전성이 프롬프트에 의존합니다.
3. 개인정보가 OCR 호출 전에 외부로 전송되고, 추론 단계의 마스킹도 불완전합니다.
4. 출력 스키마·근거 일치·임상 위험에 대한 서버 검증 없이 `success`가 반환됩니다.

면책문과 `server_reparsed` 명칭은 이 네 가지 통제의 대체물이 아닙니다.

# Pass 1 — 신뢰 경계·보안·개인정보

## P1-01. 임의 텍스트를 서버 재파싱한 뒤 실제 OCR 원문처럼 모델에 전달 (High)
- `app.py`: `/api/audit-bill`에 클라이언트가 임의의 `lines`를 보낼 수 있으며, 서버는 이를 파싱 후 모델에 "NVIDIA Vision Model의 RAW OCR"이라고 레이블링하여 프롬프트에 전달.
- 공격자가 임의의 약물/청구 항목 삽입 및 간접 프롬프트 인젝션 가능.
- `server_reparsed`는 "제출된 문자열을 서버가 다시 파싱했다"는 의미일 뿐, 원본 영수증과의 일치나 진위를 보장하지 못함.

## P1-02. 개인정보 최소화가 OCR 전송에는 미적용, 추론에서도 우회 가능 (High)
- 원본 이미지가 마스킹 전에 외부 OCR 엔드포인트(`NEBIUS_BASE_URL`)로 전송됨.
- 추론 단계의 `_mask_identifiers`는 특정 키워드가 있는 일부 숫자만 치환하므로 이름, 주소, 레이블 없는 식별자 누출 위험 잔존.

## P1-03. JIT 동의 모달의 존재와 전송 차단 분리 (High)
- 백엔드 `app.py`는 클라이언트 동의 여부와 무관하게 수신된 요청을 처리하므로, UI 단계 동의만으로는 직접 API 호출 차단 불가.

## P1-04. 인증·Origin 검증·호출량 제어 부재 (High)
- `127.0.0.1` 바인딩이라도 악성 로컬 웹페이지의 CSRF/DNS rebinding 및 리소스 고갈(DoS) 가능성.

## P1-05. 스키마 가드의 불완전성 (High)
- `setdefault`는 이미 존재하는 잘못된 타입이나 `null`을 정정하지 않음. `lines`가 문자열이나 객체일 경우 비정상 처리 가능.

## P1-06. 이미지 디코딩 실패 시 fail-open (Medium-High)
- `_prepare_image` 예외 발생 시 원본 `data_url`을 그대로 반환하여 외부에 전송.

# Pass 2 — 임상 안전·청구 추론·품질 주장 반증

## P2-01. 청구된 약물은 "현재 복약 목록"이 아님 (High — 최우선 임상 위험)
- **수술 청구서의 마취제·신경근차단제·진통제(프로포폴, 로쿠로늄 등)는 수술 중 일회성 투여 약물**임.
- 이를 현재 퇴원 후 복약과 동일하게 취급하여 "충분한 수분 섭취", "식후 복용" 같은 일상 복약 안내를 제시하면 임상 맥락 붕괴(Context Collapse).
- 수분 제한 환자에게 수분 권고 시 심부전 폐부종 위험 등 역효과 가능.

## P2-02. 고위험 약물 안전이 생성 모델에 전적으로 의존 (High)
- 단일 1회 테스트 성공이 모델의 안정적 추출과 임상 안전을 보장하지 않음.
- 약물 상호작용(DDI, 예: 마약성 진통제 + 진정제 병용 시 치명적 호흡억제) 검출 로직 부재.

## P2-03. 결정론적 파서의 구조적 한계 (High)
- `detect_currency`, `_TOTAL_KW` 등 정규식 규칙이 다국어 영수증 및 복합 청구서(Subtotal vs Total Balance)에서 오분류 가능성 잔존.

## P2-04. 영문 UI 및 인쇄 격리 (Medium)
- CSS `@media print`의 `break-inside: avoid`는 1페이지 강제가 아니며, 브라우저별 차이 및 내용 길이에 따라 2페이지로 넘어갈 수 있음.

# 배포/해커톤 제출 전 핵심 권고사항

1. **마취제/시술 약물 분기**: 수술 중 투여 약물(마취제, 근이완제)은 "일상 복약 주의"에서 제외하고 "수술 중 사용 약물 (의료진 확인 요망)"로 명확히 분기.
2. **청구서 약물 상태 명시**: "청구서에 기재된 항목이며, 실제 현재 복약 여부는 의사/약사와 확인 필요" 배너 강조.
3. **데모 데이터 워터마크**: 해커톤 데모 및 제출 시 "합성/익명화된 해커톤 데모 데이터 (Synthetic/De-identified Data)"임을 명시하여 규제 공격 방어.
